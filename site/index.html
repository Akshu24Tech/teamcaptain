The problem

Teams don't assign work in Jira

They make promises in group chats — and those promises get lost. TeamCaptain sits in a Telegram group, spots a real commitment in casual English/Hinglish, asks the accountable person to confirm, then tracks it for days: reminding, following up, escalating, and finally producing a transparent delivery report.

Why it's interesting

What makes it hard

The whole design rests on one rule: the LLM never decides facts. It points at evidence; code verifies it.

ProblemHow it's solved
Detecting commitments in casual chatLLM extraction with context, behind a cheap deterministic prefilter
LLMs hallucinate quotes, people, datesA verifier: evidence must be a verbatim substring, owners must be real members, dates are computed by code
"kal", "next friday", "end of week", "15/11"Deterministic deadline resolver with documented conventions and 30+ tests
Never tracking a wrong taskHuman-in-the-loop: only the accountable person can confirm
Workflows that last days & survive crashesInngest durable steps, waits & cancellation; DB re-checked before every message
FairnessReport counts only confirmed commitments; measures reliability, not workload

Design principles

Non-negotiable rules

🔒

The LLM never decides facts

It points at evidence; code verifies. Every LLM output field has a matching check in the verifier.

🙋

Human-in-the-loop

Nothing is tracked until the accountable person taps "Yes". Unconfirmed extractions never appear in reports.

♻️

Workflow determinism

Side effects and now() happen only inside durable steps, with IDs stable across replays.

🗄️

DB is the source of truth

Every notification re-checks status and schedule version before sending. Waits are an optimisation, not a guarantee.

💸

Free only

No paid APIs. Free LLM tiers or a local Ollama model, swapped via .env. Runs at ₹0.

📏

Measure, don't claim

Extraction changes are followed by the eval harness: precision, recall, deadline accuracy, false-alarm rate.

Quick start

Run it locally

Needs Docker and uv. A free Groq key (no card) or a local Ollama model, plus a Telegram bot token.

# install & bring up Postgres + Inngest dashboard
uv sync
docker compose up -d

# workflows + API           (terminal 1)
uv run uvicorn tc.main:app --port 8000
# Telegram bot              (terminal 2)
uv run python -m tc.bot.poller

# evaluation
uv run python -m tc.evaluation --extractor rules
uv run pytest -q   # 63 tests on SQLite, fake Telegram, fake LLM
